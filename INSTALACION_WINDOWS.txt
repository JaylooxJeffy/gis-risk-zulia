============================================================
 GIS RISK ZULIA - GUIA DE INSTALACION EN WINDOWS
============================================================
Sistema de Informacion Geografica para el analisis y la gestion
de zonas de riesgo en el estado Zulia, Venezuela.
Tiempo estimado: 30 a 40 minutos.

REQUISITOS
  1. Node.js 18 o superior (version LTS)   https://nodejs.org
  2. PostgreSQL 14 o superior              https://www.postgresql.org/download/windows/
  3. PostGIS (se instala con Stack Builder, que viene con PostgreSQL)
  4. Git (opcional)                        https://git-scm.com
  5. Cuenta de Gmail con "contrasena de aplicacion" (correos del sistema)
  6. Cuenta gratuita de ArcGIS Developers  https://developers.arcgis.com
  7. Clave gratuita de NASA FIRMS          https://firms.modaps.eosdis.nasa.gov/api/map_key/

------------------------------------------------------------
PASO 1: POSTGRESQL Y POSTGIS
------------------------------------------------------------
  a) Instala PostgreSQL. Anota la contrasena que le pongas al
     usuario "postgres" y deja el puerto 5432.
  b) Al terminar, abre "Stack Builder", elige tu servidor y en
     "Spatial Extensions" instala "PostGIS Bundle".
  c) Agrega al PATH de Windows la carpeta bin de PostgreSQL, por
     ejemplo:  C:\Program Files\PostgreSQL\16\bin
     (cambia 16 por tu version). Abre una terminal NUEVA y verifica:
         psql --version
     Si prefieres no tocar el PATH, usa "SQL Shell (psql)" del menu
     Inicio.

------------------------------------------------------------
PASO 2: OBTENER EL PROYECTO
------------------------------------------------------------
         git clone https://github.com/JaylooxJeffy/gis-risk-zulia.git
         cd gis-risk-zulia
  (o en GitHub: Code > Download ZIP, y descomprime.)
  Todos los comandos siguientes se ejecutan desde esa carpeta.

------------------------------------------------------------
PASO 3: BASE DE DATOS
------------------------------------------------------------
         psql -U postgres -c "CREATE DATABASE gis_risk_db;"
         psql -U postgres -d gis_risk_db -f database/schema.sql
         psql -U postgres -d gis_risk_db -f database/seed_factores.sql
  Cada comando pide la contrasena del usuario "postgres".
  Si dice que la extension "postgis" no esta disponible, repite
  el Paso 1b.

------------------------------------------------------------
PASO 4: BACKEND
------------------------------------------------------------
         cd backend
         npm install
         copy .env.example .env
         notepad .env
  Completa estas variables en .env:

    DB_PASSWORD     contrasena de "postgres" (Paso 1a)
    JWT_SECRET      genera uno con:
                    node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
    EMAIL_USER      tu correo de Gmail
    EMAIL_PASSWORD  contrasena de APLICACION de 16 caracteres:
                      1. https://myaccount.google.com/security
                      2. Activa "Verificacion en 2 pasos"
                      3. Entra a "Contrasenas de aplicaciones"
                      4. Genera una y pegala aqui (no uses la de tu cuenta)
    EMAIL_FROM      tu correo, o  GIS Risk Zulia <tucorreo@gmail.com>
    ADMIN_EMAIL     correo del ADMINISTRADOR PRINCIPAL. Debe ser el mismo
                    que uses en el Paso 5. A ese correo llegan las
                    solicitudes de registro y solo esa cuenta tiene los
                    permisos del administrador principal.
    FIRMS_MAP_KEY   clave de NASA FIRMS

  El resto de las variables puede quedar como esta.

------------------------------------------------------------
PASO 5: CREAR EL ADMINISTRADOR
------------------------------------------------------------
  Desde la carpeta backend:
         node scripts/crear_admin.js tu_correo@dominio.com "UnaClaveSegura123"
  - Usa el MISMO correo que pusiste en ADMIN_EMAIL.
  - La clave debe tener al menos 8 caracteres.
  - Tu usuario sera la parte del correo antes de la @ mas "-Admin"
    (por ejemplo, ana@correo.com -> ana-Admin). Tambien puedes
    entrar con el correo.

------------------------------------------------------------
PASO 6: LLAVE DE ARCGIS (FRONTEND)
------------------------------------------------------------
  a) En developers.arcgis.com crea una API key con acceso a
     "Geocoding" y autoriza este origen:
         http://localhost:5500
  b) Desde la carpeta del proyecto:
         cd frontend
         copy config.example.js config.js
         notepad config.js
     Reemplaza TU_API_KEY_AQUI por tu llave.

------------------------------------------------------------
PASO 7: ARRANCAR EL SISTEMA (dos terminales)
------------------------------------------------------------
  Terminal 1 - backend:
         cd backend
         npm start
     Debe mostrar: Servidor corriendo en http://localhost:3000

  Terminal 2 - frontend (desde la carpeta del proyecto):
         npx http-server frontend -p 5500 -c-1
     (La primera vez pregunta si instalar: responde y.)
     Alternativa con Python:  py -m http.server 5500 --directory frontend

  Abre en el navegador:   http://localhost:5500/auth.html
  Inicia sesion con el usuario o el correo del Paso 5.

------------------------------------------------------------
SOLUCION DE PROBLEMAS
------------------------------------------------------------
  "psql no se reconoce"
      Revisa el PATH (Paso 1c) o usa SQL Shell (psql).
  "extension postgis is not available"
      Instala PostGIS con Stack Builder (Paso 1b).
  "password authentication failed"
      DB_PASSWORD no coincide con la contrasena de "postgres".
  "EADDRINUSE"
      El puerto 3000 o 5500 esta ocupado; cierra el programa que lo usa.
  Mapa en blanco o error de ArcGIS
      Revisa frontend/config.js, que la llave no haya vencido y que
      autorice http://localhost:5500.
  No llegan correos
      EMAIL_PASSWORD debe ser la contrasena de aplicacion de 16
      caracteres, no la contrasena normal de Gmail.
  No puedo aprobar solicitudes ni delegar permisos
      El correo de tu cuenta de administrador debe ser igual a ADMIN_EMAIL
      en backend/.env. Reinicia el backend despues de cambiarlo.

------------------------------------------------------------
OPCIONAL: DATOS DE SUELO FAO (HWSD)
------------------------------------------------------------
  Estos datos NO vienen en el repositorio por su tamano. Sin ellos
  el sistema funciona completo y solo la validacion de salinidad del
  suelo (FAO/IIASA HWSD v2.0) queda sin datos. Esa validacion usa las
  tablas hwsd_raster y hwsd_layers de la base de datos.
